# Native workspace runtime review

[Simplified Chinese version](native-runtime.zh-CN.md) · [Machine-readable inventory](native-runtime.json)

Reviewed on 2026-11-05 for the existing single-owner local Mac. The exact OS build, installed executable hashes, license sources and operational conclusions are recorded in the inventory. No executable, operating-system image or extra package is downloaded, modified or redistributed by this implementation.

The installed Apple `sandbox-exec` runs the platform-owned file-operation worker under a deny-by-default Seatbelt policy. Only the selected Node executable can start. User file contents, filesystem writes, network connections and subprocess creation are denied. The worker reads bounded text snapshots over stdin, applies list/read/literal-search/write operations in memory and returns results over stdout. The database broker separately validates ownership, operation IDs, expected revisions and the current Run lease before publishing durable changes. Imported text is never evaluated as code.

The Pi host remains trusted application code outside this file worker so it can contact the configured model. It receives only the selected provider credential and controlled settings; file tools are IPC requests to the broker. No repository tool, shell, dynamically discovered extension or executable skill is enabled. Worker failure cannot fall back to unsandboxed file execution.

The policy permits OS library/share reads and directory metadata. It excludes `/System/Volumes/Data` from content access, and readiness tests verify a private sentinel, its Data-volume alias and its symlink are unreadable. Startup also verifies network, host-write and subprocess denial. Parent supervision sets a five-second deadline, bounded stdin/stdout and a 64 MiB V8 heap; the heap flag is not an OS-level RSS guarantee. Files are limited to 128 entries, 65,536 bytes each and 512 KiB per serialized snapshot; individual tool results have tighter output limits. Each operation runs in a new worker. Persistent working files are immutable PostgreSQL revisions, not a host directory mount.

Apple's installed manual marks `sandbox-exec` deprecated. The local provider therefore verifies macOS 26.5.1/build 25F80 and the reviewed Node 22.20.0 arm64 and Apple executable hashes, capability-probes real enforcement and fails closed on unsupported/restricted hosts or unreviewed binary versions. `nativeRuntimeIdentity()` exposes the binary and policy hashes for execution records. It is a local macOS implementation, with no VM, Linux or hostile multi-tenant workload guarantee. A later execution provider requires its own review and acceptance evidence.

The Apple OS component uses the [macOS Tahoe 26 license](https://www.apple.com/legal/sla/docs/macOSTahoe.pdf). The reviewed path is existing licensed use on Apple hardware, including the applicable commercial-enterprise grant. This does not authorize redistributing Apple's binary or operating shared/leased/cloud OS services; those uses have separate restrictions and require their own review. Apple explains that [the applicable acquisition-time license controls](https://www.apple.com/legal/sla/).

The existing Node 22.20.0 runtime is invoked unmodified. Its selected-release [LICENSE](https://github.com/nodejs/node/blob/v22.20.0/LICENSE) contains Node's MIT terms and bundled component notices; it is not an MIT-only binary. No Node archive is bundled here. A customer-hosted image or runtime distribution must preserve and review the complete selected release notices separately from the npm dependency inventory.
