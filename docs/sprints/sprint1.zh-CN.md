# Sprint 1 单 Agent 聊天

状态：实现已交付；最终真实 Pi 验收因 OpenAI 认证受阻

创建日期：2026-11-04

[英文版](sprint1.md) · [目标架构](../architecture.zh-CN.md) · [Agent 管理配置](../admin-settings.zh-CN.md)

## Sprint 目标

交付可用的私聊应用：创建对话、发送消息、观看一个 Agent 逐步回复、停止生成，并在导航或刷新后返回已持久化的历史记录。客户端使用 React 和 shadcn/ui，服务层使用 Node.js。Pi 仍是首个真实 Agent 集成，本 Sprint 将其限制为文本对话。

这是首个交付切片，并非整个目标架构的实现。群聊和 Agent Team 延后交付。保留合适的标识符和集成边界，不为未来功能实现团队表、委派工具或调度器。

## 范围与优先级

### 必需功能

- 创建、列出、打开、重命名和归档私聊。默认列表隐藏已归档聊天；如果对话有活跃的 Run，在其停止前拒绝归档。本 Sprint 不包含永久删除。
- 按服务端稳定顺序显示消息，并提供加载中、空状态、错误、待发送、生成中、已停止和已中断状态。根据第一条用户消息持久化默认标题，不额外调用模型。
- 发送非空文本，在导航期间为每个对话保留未发送草稿，支持 Enter 发送和 Shift+Enter 换行，并且绝不在输入法组合输入期间提前发送。
- 安全渲染 Markdown，支持代码块和复制操作。禁用原始 HTML 执行和不安全的 URL 协议。复制代码或消息时保留原始文本。
- 将流式回复显示在一条助手消息中，不为每个增量创建新气泡。保留读者的滚动位置，在其阅读较早消息时提供新输出提示。
- 在生成期间显示停止操作，并区分待取消和已确认终止。保留部分输出及其实际终态。
- 在刷新或路由切换后恢复聊天历史和活跃执行。浏览器断开连接不得取消由服务端管理的 Run。
- 提供对应完整的 `en` 和 `zh-CN` 文本、无障碍键盘与焦点行为，以及可用的桌面和移动端布局。

### 完成必需工作后的可选功能

只有在核心流程和可靠性检查通过后，才可添加标题搜索、深色模式、更丰富的代码高亮和其他小幅视觉改进。它们不能替代必需的流式传输、持久化或错误处理。

### 明确延后的功能

Agent Team、群聊、提及、成员管理、任务 DAG、多 Agent 执行、附件、仓库导入、文件修改、终端、应用预览、工具审批、完整用户账号和 OIDC、组织、计费、后台计划任务，以及其他 CLI 集成均延后交付。

2026-11-05 的单一所有者管理配置完善已加入模型选择和服务端凭据输入，包括加密设置、独立回复语言及受准入保护的运行时修改；它没有引入多用户身份系统。详见 [Agent 管理配置指南](../admin-settings.zh-CN.md)。

## 服务设计

### 最小运行拓扑

```text
React 客户端
    -> Node.js API：对话与消息命令，以及 SSE
        -> PostgreSQL：应用状态、事件日志、命令发件箱
        -> 内部派发器：每个对话一个活跃 Run
            -> 模拟适配器或受监管的 Pi 宿主进程
                -> 获授权且已配置的模型服务（仅 Pi 模式）
```

本 Sprint 的派发器运行在 API 服务内部。将其接口独立保留，以便后续用工作进程替换。领取任务的状态和活跃 Run 约束存储在 PostgreSQL 中，而不仅存在于内存映射中。实施较小且可配置的服务并发上限和生成超时；明确拒绝超限受理，不得静默积压无限工作。

在专用子宿主进程中启动 Pi，设置显式工作目录和按对话隔离的持久化会话存储。禁用所有内置工具、自定义工具、资源发现、钩子、扩展和项目内容，除非它们为纯文本操作所必需，且已经过明确审查。任何用户请求都不能启用工具或选择任意提供方 URL。验证运行时暴露的工具列表为空；除扩展发现外，还要禁用技能和仓库指令。在服务端配置模型和凭据；绝不将密钥放入前端环境变量、API 响应、日志或已提交文件中。

进程边界不是用于执行不可信代码的沙盒。本 Sprint 接收文本，不执行仓库代码。在引入可执行工具或用户提供的扩展前，先建立真正的沙盒边界。Pi 宿主必须在与父进程断开连接时关闭，具有受限的生命周期，并拒绝过期执行尝试的输出。

### 数据模型

| 记录 | 必需信息 |
| --- | --- |
| Conversation | 对话；ID、所有者 ID、`kind = direct`、标题、归档时间戳、创建和更新时间戳 |
| Message | 消息；ID、Conversation ID、用户或助手角色、稳定显示顺序、内容、投递或生成状态、客户端消息 ID、时间戳 |
| Run | 运行；ID、Conversation ID、触发的用户 Message、助手 Message、适配器模式、状态、请求键和哈希、取消和错误信息 |
| ConversationEvent | 对话事件；事件 ID、Conversation ID、对话内序号、Run 和 Message 引用、事件类型、载荷 |
| AgentSession | Agent 会话；Conversation 和 Agent 作用域、原生会话引用、运行时版本、持久化位置、最后已知状态 |
| CommandOutbox | 命令发件箱；稳定派发 ID、Run ID、派发状态、执行尝试身份和时间戳 |

在一个事务内持久化用户 Message、Run、助手占位消息、初始受理事件和派发记录。在多个标签页和重复 HTTP 请求之间，强制保证每个 Conversation 只有一个活跃 Run。使用相同请求正文重复提交幂等键时，返回原始结果；使用不同内容重复提交同一键时，返回冲突。在将重复请求以忙碌为由拒绝前，先检查已有请求键。

本 Sprint 不创建 Team、TeamBinding、成员关系、Project 或任务图存储。将 Run 与 Message 分开，避免执行生命周期扭曲聊天日志。添加模式迁移和用于开发、测试的固定数据数据库；浏览器存储不是具有权威性的历史记录。

### API 接口

| 方法与路由 | 用途 |
| --- | --- |
| `GET /healthz` | 检查服务存活状态，不暴露配置机密 |
| `GET /api/conversations?cursor=&limit=` | 分页获取最近的未归档对话 |
| `POST /api/conversations` | 创建空的私聊 |
| `PATCH /api/conversations/:id` | 重命名或归档，并保护活跃 Run |
| `GET /api/conversations/:id/messages?before=&limit=` | 读取历史和当前 Run 状态，同时返回快照事件游标 |
| `POST /api/conversations/:id/messages` | 使用 `Idempotency-Key` 原子受理文本和单 Agent Run |
| `GET /api/conversations/:id/events?after=` | 重放并订阅 SSE 事件 |
| `GET /api/runs/:id` | 检查获授权的 Run，包括取消结果 |
| `POST /api/runs/:id/cancel` | 请求幂等取消 |

返回稳定错误，例如 `VALIDATION_ERROR`、`CONVERSATION_NOT_FOUND`、`CONVERSATION_BUSY`、`IDEMPOTENCY_CONFLICT`、`AGENT_NOT_CONFIGURED`、`UPSTREAM_RATE_LIMITED` 和 `RUN_INTERRUPTED`，并附带本地化所需参数。派发前校验文本大小、分页边界、标识符归属、内容类型和并发限制。

### 流式传输与状态核对

先持久化带序号的事件，再广播。通知仅用于唤醒；数据库日志仍是重放来源。从历史响应的游标开始订阅，确保初始历史读取与 SSE 连接之间产生的输出不会丢失。快照内容和游标必须代表同一个一致视图。

事件涵盖消息受理、助手增量和 Run 状态变更。为增量附带助手消息版本或偏移量，或在重新同步时根据规范快照重建该消息，确保重新连接不会重复追加文本。终态事件提交规范的最终或部分内容和状态。保持有界缓冲区并发送心跳；游标过期时必须显式重新同步。

切换聊天时，解除旧 UI 订阅，但不停止旧 Run。切换回来时恢复当前状态。一个 Run 活跃期间，新的生成请求返回明确的忙碌结果；本 Sprint 不实现执行中引导或第二条消息队列。网络重试复用相同请求键；重试失败的生成是用户显式发起的新操作，不是自动重复模型请求。

### 取消与重启语义

使用 Run 状态 `queued`、`running`、`cancelling`、`completed`、`failed`、`cancelled` 和 `interrupted`。取消排队中的工作会阻止派发。生成期间取消时，请求 Pi 中止，并保持 `cancelling`，直到观察到终止，或生命周期受限的宿主被强制停止。完成和取消通过条件数据库状态转换进行竞争，以确保只有一个终态结果；停止操作不能将已经完成的回复覆盖为已取消。

失败、取消或中断后，保留部分助手内容并显示其状态。终态之后到达的增量会被忽略。停止本地请求不保证提供方会立即停止计费。

服务重启时，核对遗留的派发记录，并在将尚未解决的已受理 Run 标记为 `interrupted` 前，确认先前宿主已无法继续执行。本 Sprint 中，这也包括已受理但尚未派发的排队工作：终结其发件箱条目，不自动启动。不要盲目重新启动任何旧 Run。在确认先前宿主已终止前，受影响的 Conversation 不接受新的生成。在受理后续显式继续执行前，先核对 Pi 和会话状态。本 Sprint 承诺持久化聊天历史和支持浏览器重新连接，不承诺在进程崩溃后精确恢复到工具级别或继续原模型请求。

## 演示与完成定义

以英语和简体中文分别演示以下内容：

1. 新建聊天、发送消息、接收流式回复，并复制代码块。
2. 发送第二条引用第一条内容的消息；同一对话保留上下文。
3. 打开另一聊天；其历史记录和 Agent 上下文相互独立。
4. 离开并重新打开正在执行的聊天，然后刷新；回复得以重建，不产生重复气泡或重复文本。
5. 将同一请求提交两次；只接受一个逻辑 Run 和一次模型派发。另一个并发请求收到忙碌响应。
6. 在流式输出期间停止；保留部分输出，最终状态反映实际观察到的结果。重复取消不会产生不良影响。
7. 触发模拟服务提供方错误和临时事件流断开；展示可操作的状态，不静默重新发送生成请求。
8. 在执行期间重启服务；历史记录保留，未解决的工作转为中断，而非完成或自动重跑。
9. 重命名并归档未在执行的对话；它从默认列表消失，但不硬删除历史记录。
10. 使用移动端布局、键盘导航和中文输入法，草稿不丢失，且不在输入法组合输入期间发送。

完成定义还要求提供迁移/配置文档，通过 typecheck/build 和有针对性的 API/UI 测试，实现安全的 Markdown 渲染、消息/凭据脱敏、所有权检查、有界的输入/工作限制，并使实际产物通过商业依赖门禁。

模拟模式必须能够在没有外部凭据的情况下运行。真实 Pi 验证需要通过服务端配置提供已获授权且可用的模型凭据。如果无法提供该凭据，将 S1-07 和真实集成结果标为受阻/未验证；除非明确推迟该范围，否则不能将仅有模拟的演示报告为已完成 Pi 集成或已完整完成本次迭代。

## 测试与交付边界

大多数测试使用确定性的模拟测试数据。集成测试聚焦于原子性接收、同键冲突、单一活跃 Run、快照/重放竞态、取消与完成的竞争、部分持久化和重启行为。加入浏览器场景，覆盖导航、流式输出、语言区域切换、输入法输入和安全的 Markdown。屏幕阅读器播报概括状态和已完成内容，而非逐个 token 播报。避免编写仅重复生成组件实现的测试。

开发服务默认绑定回环地址，并使用由服务端确定的固定开发所有者。绝不将客户端提供的所有者 ID 视为授权依据。强制检查预期 Host/Origin、显式允许的开发源，并为使用 cookie 身份验证的命令实施适当的 CSRF 防护；禁止对已认证请求使用通配 CORS。不要将 API 凭据放入 SSE URL。

共享预览需要身份验证访问门禁，并为整个应用提供 TLS，而不只是首页；API/SSE 访问也必须受到保护。完整的平台身份系统和多租户能力声明推迟实现。公开的无身份验证部署或生产就绪声明均不属于 Sprint 1。

审查 React、shadcn 源码、所选底层基础组件、Tailwind、Fastify、数据库客户端、Pi 软件包、Markdown 渲染器、图标、构建/测试工具及所有传递组件的精确版本。上游 [shadcn/ui MIT 许可证](https://github.com/shadcn-ui/ui/blob/main/LICENSE.md) 是有用证据，但不代表每个生成的依赖或第三方注册表条目都已获准。依照[项目政策](../../AGENTS.md)保留所需许可证和声明材料。

任何依赖、CI 门禁或应用功能，都不能仅因出现在本计划中就视为已实现。
